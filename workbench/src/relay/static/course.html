Who this is for

You know APIs.
Now work on the AI engineering.

This course assumes you can read application code, use Git and a terminal, and understand HTTP APIs, validation and basic authentication. Familiarity with Python is useful; you do not need to have built an agent system before.

The FastAPI application, Swagger documentation, data fixtures and ordinary API controls are prepared before class. Contact time goes into grounding, tool execution, evaluation, engineering loops and operational judgment.

The practical project

Relay, a support resolution workbench

Explore Relay ↗

A customer at fictional Nigerian logistics company Kora Dispatch asks about a delayed parcel. The agent needs shipment facts, approved policy and a defensible next step. The AI assists; the application and supervisor control the action.

  1. 01

    Investigate

    Read the case and its shipment facts.

  2. 02

    Ground

    Retrieve permitted policy and show the evidence.

  3. 03

    Propose

    Suggest a resolution within server-enforced limits.

  4. 04

    Review

    A supervisor approves the exact action; record it once.

Synthetic cases and policies keep the exercises reproducible. The workshop sends no customer messages or real payments.

Contact 1

60 minutesCourse outline ↑

Grounded AI application engineering

From a model response to a trustworthy application

Follow one support question through the working application: hybrid RAG, read tools, conversation context, execution stages and evaluated answers.

  • OpenAI integration: Responses API, SDK usage, prompt and context design, structured outputs, refusals, incomplete responses and real SDK streaming with validated completion.
  • Retrieval-augmented generation (RAG): chunking, OpenAI embeddings, persistent vector search, permission filters, hybrid comparison and source citations; relevance, abstention and the distinction between retrieval quality and answer support.
  • Tools and execution: function schemas, argument validation, tool results, fixed workflows versus bounded agent loops, direct versus LangGraph execution, and the separation of read tools from business actions.
  • State and guardrails: stateless versus stateful interactions, saved history versus explicit caller-managed context; a separate OpenAI response-chaining/Conversations comparison, current-source checks, deletion, injection risks, role isolation and human approval.
  • Quality and observability: golden datasets, evaluation harnesses, retrieval and answer checks, separately budgeted model judges and run-bound human labels; nested Langfuse observations, usage, latency, supplied-price cost estimates and a bounded Codex introduction.
Demonstrate live

One question → retrieved policy → grounded answer, in one app.

Embeddings/Qdrant, native/LangChain chunking, structured Responses, scoped tools, context, streaming and the direct/LangGraph reference.

Compare with evidence

Failure cases, retrieval scores, supported claims, nested traces, model settings and evaluation reports.

Practical AI engineering with governed Codex

Build, verify and review with Codex

Start with a short working RAG walkthrough, then practise governed Codex engineering: scope the task, use tools and skills, verify the change and prepare it for review.

  • RAG walkthrough: parsing, chunks, embeddings, Qdrant, hybrid ranking, model input, streaming and citations.
  • Codex controls: model and effort, Plan mode, Goals, sandbox and approval boundaries.
  • Reusable engineering: clear task prompts, AGENTS.md, general review/browser skills and a reusable ingestion skill.
  • Tools and context: external documentation MCP, permissions, handover, memory and caching distinctions.
  • Delivery: isolated worktree, test/repair loop, browser evidence, diff review and a local PR draft; prepared automation reference.

Governed knowledge and durable automation

Give automation useful capabilities and clear boundaries

Improve a prepared source-ingestion path, review material before publication, and examine a workflow that survives an interrupted worker.

  • Knowledge governance: parsing and chunking, metadata, provenance and rights, duplicate detection, hostile content, human review and publication.
  • Reusable instructions: skills, SKILL.md resources, AGENTS.md scope, skill testing and the distinction between instructions, MCP capabilities and backend authority.
  • State and orchestration: conversation, application and workflow state; execution harnesses versus evaluation harnesses; LangChain components and LangGraph state transitions.
  • Durable work with Temporal: workflows and activities, approval waits, worker restart, bounded retries, cancellation and one effect despite repeated events.
  • Scheduling and events: manual versus scheduled triggers, timezones, overlap, catch-up, pause/cancel, asynchronous inference and signed webhook boundaries.
Evidence to inspect

An unpublished candidate, a reviewed-source skill, a publication record and an approval workflow that resumes safely.

Forward-deployed engineering and readiness

Decide what is ready to put in front of a customer

Connect technical evidence to the customer workflow, operational constraints and adoption. Practise a go, conditional-go or no-go decision.

  • Discovery: user pain, workflow baselines, stakeholders, data owners, AI suitability, non-AI alternatives and a thin vertical slice.
  • Pilot gates: representative evaluations, failure slices, permission tests, latency, cost per successful task and stakeholder acceptance.
  • Governance and operations: identity, secrets, retention and residency, audit trails, deployment controls, incident ownership and escalation.
  • Recovery and adoption: model outages, stale knowledge, revoked access, duplicate events, rollout cohorts, rollback, user training and handover.
  • Further readiness: compare advanced options and review API and Codex learning gaps separately against the applicable certification objectives.
Evidence to inspect

A discovery brief, a pilot decision, an incident/rollback exercise and a handover plan. Learner presentations are not required.

Further depth

The wider AI engineering toolkit

The core demonstrations are deliberately narrow. These topics extend them through reference walkthroughs and guided exercises; they are not additional features to build in four hours.

Retrieval and context engineering Inspect + practice

HTML, PDF and image extraction; extraction confidence; chunking and metadata; deeper tuning of Contact 1 embeddings, vector and hybrid retrieval; reranking and query rewriting; conflicting or stale evidence; index readiness, freshness, deletion and source provenance.

Agents, runtimes and memory Inspect + practice

Deterministic workflows versus agents; bounded execution harnesses; tool discovery, programmatic and asynchronous calls; parallel and dependent tools; handoffs and multi-agent coordination; direct Responses versus Agents SDK and managed runtimes; LangChain, LangGraph and Temporal responsibilities; caller-managed history, conversation state, compaction and long-term memory with retention and deletion.

Evaluation, safety and observability Inspect + practice

Reviewed golden and held-out datasets; deterministic graders, calibrated model judges and human review; repeated runs and failure slices; whole-run tool/action evaluation; redacted Langfuse traces; prompt/model/corpus versions; prompt injection, data leakage, moderation versus business rules, sandboxing and exact-action approvals.

Performance and model choices Inspect + practice

Model selection and routing; supported reasoning controls; token and context budgets; prompt caching; batch and flex processing; background responses, polling and cancellation; bottleneck analysis and fallback quality. Compare quality, latency and cost on the same task.

Developer automation and integrations Inspect + practice

Codex SDK, non-interactive execution, CI and cloud workflows; worktrees and delegation boundaries; reusable skills and plugins; MCP tools, resources, prompts and transports; scoped Linear/GitHub workflows; scheduled regression triage, webhook verification and integration permission review.

Multimodal systems and model adaptation Inspect + practice

Document/image provenance, vision and audio intake, transcription, voice and realtime interaction, interruption and cancellation. Decide when prompts, context or RAG are sufficient and when fine-tuning or distillation warrants a measured experiment.

How to read the curriculum

Broad grounding.
Selected deep demonstrations.

Demonstrate: execute or improve a prepared scenario together. Inspect: trace a reference implementation and its evidence. Practise: complete a guided extension and verify it independently.

Four facilitated hours establish a connected mental model and selected engineering skills. Independent proficiency requires practice and review. Certification readiness needs a separate check against the relevant official objectives.

Class examples identify whether they run live, locally as fixtures, or as disclosed replays. Accounts and integrations are preflighted for the chosen demonstration mode.

The story behind Relay

The Kora Dispatch context

Their support team is overwhelmed with customer questions about late deliveries, address changes and damaged parcels. Many of these questions are similar, but agents still have to look up each shipment, find the relevant policy and work out what they can offer the customer. As the queue grows, customers wait longer and agents have less time for complicated cases.

The team wants AI to help agents find the right information and prepare answers more quickly, while keeping people responsible for decisions that need approval.

Imagine one of those messages comes from a customer who asks:

“I paid ₦8,000 for express delivery, but my parcel arrived two days late. What can you do about it?”
