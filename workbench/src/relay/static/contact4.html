07 · Prompt caching

Cache the stable prefix, not the changing question.

Caching can reuse model work when the rendered prompt prefix matches.

instructions + tools + examples→new user/task data
Keep stable

System/developer instructions, tool definitions and shared reference material.

Append

New turns and tool results should extend history instead of rewriting it.

Measure

Inspect cached tokens, cache-write tokens, latency and total cost.

A cache hit is not guaranteed. Model, tools, settings, prefix equality and lifetime all matter.

Source: OpenAI Prompt Caching

Speaker notes

Prompt caching is an optimization with observable usage and cost signals, not a promise that every request will be cheaper.

08 · Breakpoints

A breakpoint is a cache boundary.

It is not a debugger pause. It marks the exact end of content worth writing to the prompt cache. 

{
  "prompt_cache_options": { "mode": "explicit", "ttl": "30m" },
  "content": [
    { "text": "Stable instructions…",
      "prompt_cache_breakpoint": { "mode": "explicit" } },
    { "text": "Changing user request…" }
  ]
}
ImplicitProvider chooses an eligible boundary.
ExplicitYou mark the reusable boundary.
SuffixChanging content can stay uncached.
CheckRules vary by model and API version.

Source: Prompt caching guide

Speaker notes

Use the current API documentation and model support matrix before teaching an explicit breakpoint as an available production feature.

10 · Exam prep

Deployment-practitioner study checklist.

These are practical study themes—not an official exam blueprint.

Codex deployment
  • Scope the task and define “done”.
  • Plan before editing; review the diff.
  • Know sandbox, approvals, credentials and network boundaries.
  • Run proportionate tests and report evidence.
  • Keep tool connections least-privilege.
API deployment
  • Start with representative evaluations.
  • Choose model and reasoning effort for the workload.
  • Instrument latency, tokens, cache, errors and cost.
  • Handle overload, retries, safety identifiers and approvals.
  • Use HTTP or a tunnel for remote MCP clients.

Source: API deployment checklist · Codex training

11 · Close

The invariant: make the boundary explicit.

A good MCP demo ends with a safe next step, not just a successful tool call.

01

Know what the server can read and what it cannot change.

02

Choose stdio, tunnel or HTTPS based on the client.

03

Inspect tools and permissions before using real data.

04

Keep stable context cacheable; measure the result.
