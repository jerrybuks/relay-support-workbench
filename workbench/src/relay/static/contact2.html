Speaker notes

In the demo, the six displayed numbers are a preview of a full 1,536-number vector. text-embedding-3-small defaults to 1,536 dimensions; text-embedding-3-large defaults to 3,072. The third-generation models support shorter vectors through the dimensions parameter. The embedding output must match the Qdrant collection configuration. A different embedding model needs its own rebuilt index even if its vector length happens to be the same. Relay rejects incompatible index settings; reducing dimensions is an experiment to evaluate, not an automatic improvement.

Why chunk, and how should we split?

Retrieve the relevant passage, keep useful context and avoid sending the whole document.

Fixed-size

Split by a character or token limit, often with overlap. Simple; can cut across a rule.

Recursive

Try paragraph, line and word boundaries before smaller splits, within a size limit.

Semantic

Use meaning or topic changes to choose boundaries. More processing; quality needs testing.

Demo: size-based, word-aware chunks · 320 characters · 64-character target overlap.

Code · click to copy

Speaker notes

We chunk so retrieval can select a focused passage instead of treating the whole PDF as one item or sending everything to the answer model. The passage must still retain enough context to support the answer. Fixed-size splitting uses a chosen character or token count; overlap repeats nearby text at boundaries. Recursive splitting tries larger natural boundaries first, then smaller ones until the text fits. Semantic chunking uses changes in meaning, often with sentence embeddings, to choose boundaries; that extra processing is not automatically a quality improvement. Our default is a size-based splitter that avoids cutting words. The optional LangChain recursive splitter is implemented; semantic chunking is an explanation here, not an implemented option. The displayed settings use characters, not words or tokens. Check actual chunks and evaluate retrieval before choosing a strategy. PDF extraction happens before chunking; scanned pages need OCR, which this demo does not implement.

References: LangChain recursive splitting; RAG chunking strategies.

Similarity, top-k and hybrid search.

Cosine + threshold

Higher cosine means more similar. The cutoff rejects weak vector matches.

Top-k + hybrid

Top-k limits results. Hybrid combines vector and keyword rankings.

Access filters

Tenant and role checks restrict which passages can be returned.

Demo: top-k 3 · cosine cutoff 0.4, uncalibrated. A hybrid score is not cosine.

Code · click to copy

Speaker notes

Cosine compares vector direction; it is not a probability that an answer is correct. Euclidean distance compares straight-line distance, where lower is better. A high threshold can lose useful passages and a low one can admit noise; calibrate with reviewed questions. Relay combines vector and SQLite keyword rankings using reciprocal rank fusion. The fused score is not the cosine value. Authorized keyword results can enter independently of the vector cutoff. Metadata access filters apply to both paths. ANN is a technique used for efficient search at scale; this tiny local index does not demonstrate production performance.

Contact 02 / 09Use when needed

Codex engineering

Context, compaction and memory.

Context · this request

The instructions, conversation, files and tool results supplied to the model.

Compaction · this thread

Condenses earlier work to keep going within the context limit. Details can be lost.

Memory · future chats

When enabled, Codex recalls useful context from eligible earlier chats.

Keep required rules in AGENTS.md and exact results in a handover.

Speaker notes

Context is what the model receives now. As a thread grows, compaction carries key prior state forward in fewer tokens; it is not a perfect copy of every earlier detail. Keep exact commands, decisions and results in files that Codex can read again. A fresh task needs the relevant files and a short handover.

Local Codex memories are a separate feature, off by default. When enabled, eligible earlier chats can contribute to memory files in the background. Use /memories where supported to control whether this chat uses memories or contributes to future memories. Saying “remember this” is not a guaranteed immediate save. For a rule that must apply, ask Codex to update the appropriate AGENTS.md and review the diff. These are stored context mechanisms, not changes to model weights. Do not enable memory during class just to demonstrate the distinction; show the available controls and explain them.

Sources: https://learn.chatgpt.com/docs/customization/memories and https://developers.openai.com/cookbook/examples/gpt-5/codex_prompting_guide

Speaker notes

Think of two requests that begin with the same project rules and tool definitions. The provider can reuse eligible computation for that matching beginning. It still processes the new part. This can reduce latency and input cost.

Official docs · checked 23 Oct 2026Effort · Speed and usage

Speaker notes

Medium and High control reasoning effort. For Sol I start with the client default; the current guidance starts Luna at High and Astra at Light. Labels and supported levels vary. More effort does not guarantee a better patch.

Fast is a different setting. In the CLI, /fast toggles it when the model supports it; the IDE has a speed control where available. With ChatGPT sign-in, the documented Fast rate is 2.5 times Standard included usage, or twice the rate for purchased credits. That is a usage multiplier, not a promise that the whole task finishes 2.5 times faster.

API-key billing follows API pricing instead. Ultrafast is another, plan-limited tier with higher usage; I do not need it for this exercise. I check the selected speed rather than assuming Fast is on.
