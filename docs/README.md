# Relay documentation

Product, engineering and teaching documentation for **Relay**, the API-first support-resolution workbench used throughout the four training contacts.

Start with the document that matches your task:

1. [Product and technical design](PRODUCT_AND_TECHNICAL_DESIGN.md): product decision, architecture, contracts, security, milestones and limitations.
2. [Facilitator runbook](FACILITATOR_RUNBOOK.md): preparation, timed four-contact progression, live demonstrations and recovery.
3. [Test and evidence plan](TEST_AND_EVIDENCE_PLAN.md): acceptance, evaluation, verification and readiness evidence.
4. [AI engineering and FDE blueprint](AI_ENGINEERING_AND_FDE_BLUEPRINT.md): expanded curriculum inventory and breadth/practice mapping.
5. [Implementation plan](IMPLEMENTATION_PLAN.md): execution stages and current status.
6. [Checkpoint guidance](CHECKPOINTS.md): selecting known working states and reference profiles.
7. [Delivery backlog](ISSUES.md): remaining integrations, reviews and rehearsal work.
8. [Contact 1 preparation](teaching/CONTACT_1_PREPARATION.md): launch profiles, live preflight, evaluation and rehearsal.
9. [Coverage audit](teaching/CONTACT_1_COVERAGE_AUDIT.md): verified application paths, corrected omissions and later-contact implementation gaps.
10. [Contact 2 rehearsal guide](teaching/CONTACT_2_REHEARSAL_GUIDE.md): updated two-hour RAG and governed Codex session, code walkthrough, talk track, prompts and preparation gates.
11. [Participant practice](teaching/RELAY_PRACTICE.md): exercises and evidence expected beyond the facilitated sessions.

Deployment setup is in [the hosted workshop guide](DEPLOYMENT.md): a free single-service Render Blueprint, with ephemeral data and public AI request limits.

These files are the active specification. Superseded game code and documents have been removed from the working tree and remain recoverable from historical Git tags. Their results are not evidence for Relay.

Prepare ordinary API engineering before class. Preserve meaningful instructor engineering in Contacts 1–3, separate before/intermediate/reference states, zero-key local fallback, source/data governance, reproducible failures, tests and measured evidence. Contact 4 retains release decisions and separate API/Codex readiness without requiring learner presentations.

All broader capabilities need an explicit coverage mode and honest verification status. Four contacts provide broad grounding and selected deep demonstrations; guided practice is required to assess independent proficiency. Production deployment and external integration writes are not authorized by local curriculum preparation.
